Microvania Toolkit — Creator Master Guide#

This is the master guide for making a small exploration platformer with the Microvania Toolkit. It assumes you have never used Tiled or Defold. Follow the first-world walkthrough in order once; after that, use the recipes and quick reference when you return to your project.

The supported workflow is visual and Tiled-first. You create rooms and place objects in Tiled, arrange rooms in a Tiled world or the Layout Editor, run menu commands in Defold, and play. You should not need to edit Lua code or anything under mvtk/.

Scope: Microvania is for compact two-to-three-hour exploration games. It supports simple enemies, collectibles, gates, hazards, traversal, lightweight NPC/dialogue objects, audio/visual zones, and the compact five-template boss set.
Beginner note: Menu names in this guide are written exactly as they appear. File ▸ new_room_blank means open the File menu in Tiled and click new_room_blank. Text in code style is a filename, folder, property, or value.

Start here — make three rooms, then play#

You only need this path to get started. Use the linked instructions when you need help. The object recipes, art options, and configuration reference later in this guide are for features you choose to add.

Step Do this You are done when
1. Open the tools Extract the toolkit. Open game.project in Defold and run Project ▸ Set Up This Toolkit. In Tiled, tick the defold and lua plugins under Edit ▸ Preferences... ▸ Plugins, open MVTK.tiled-project and click Enable Extensions if Tiled asks. Tiled has File ▸ new_room_blank and File ▸ Export Current Room.
2. Make three rooms Make a tileset for your art, with collision shapes on its solid tiles. Then follow the room walkthrough: use your art's tile size, paint the room, collision and door markers, and place one player start. Save/export each room. All three rooms have a .lua and .tilemap export.
3. Prepare the game Stop the game. In Defold run Reload Editor Scripts → Prepare & Check → Build, in that order. Exact clicks. Validation passes and the title screen opens.
4. Connect and play Open Layout Editor, click Rescan Rooms, snap matching doors, click Export, wait, then Menu → Play Game with an empty slot. Exact clicks. You can walk between the rooms, save, quit, and continue.

Keep the starting presets for this first pass. Use Game Settings after Prepare & Check when you want to change movement or abilities. Stop the game first, open Project ▸ Game Settings…, then save and Build to test. You do not need to tune every setting before making your first world.

The room layers you need:

Layer Put this on it
bounds An unbroken one-tile ring marking the room footprint. Keep it closed at doors too.
art/environment and solid Visible art and blocking tiles. Give solid tiles collision shapes in the tileset.
grapple Paint where the hook may catch. Add visible hook markers on the art layers; this layer adds no art or player collision.
exit/door_left, door_right, door_top, door_bottom Exit markers where rooms should connect. Leave a real opening in the art/collision.
templates Ready-made objects, including the one intended player_start.

If a step fails, fix its first error before continuing. The troubleshooting section is arranged in the same order. Do not edit generated room files or framework code to get past an error.

Returning Creator Quick Reference#

After editing a room: save/export it in Tiled → stop the game → Prepare & Check → Build → Layout Editor: Rescan Rooms → Export → Play Game.

What changed? What to do next
Room art, collision, objects, tileset, or room music Follow the room-edit loop above for every changed room.
Toolkit/editor scripts Reload Editor Scripts first, then follow the room-edit loop.
Room placement only Layout Editor ▸ Export, then Play Game.
One room's content Save the active map, then File → Export Current Room. In Defold, Prepare & Check → Build; the exported world placement stays the same.
Tiled world placement, membership, or room size File → Export All Maps and Tiled World, then Defold Prepare & Check → Build → Play Game. World workflow.
Movement or ability tuning Stop the game, use Project ▸ Game Settings… → Save and Prepare & Check, then Build and test. Published values override baseline config files.
Enemy PNG frames or separate music files Prepare & Check syncs both; then Build.
Ready to distribute your game Follow the release steps.

Export choices: Tiled exports a room or all maps plus a world. Prepare & Check publishes a selected Tiled world; Layout Editor Export publishes manual placement. Defold Export Game creates the separate project you bundle for players. Build starts the game for testing.

1. Understand The Two Programs#

You will use two applications, each for a different job:

Program What you do there
Tiled Draw each room, paint collision and door markers, place ready-made templates, and export the room.
Defold Import art, generate playable rooms, validate the project, run the Layout Editor, and build/play the game.

The toolkit connects them. A normal room passes through this sequence:

Your .tmx room in Tiled
        ↓  Export Current Room
<room>.lua + <room>.tilemap
        ↓  Prepare & Check
Defold collection + factory + baked game objects
        ↓  Layout Editor Export
Published world layout used by Play Game

Essential words#

Word Plain-language meaning
Room One level map. One Tiled .tmx becomes one playable Defold room.
Tile One grid-sized piece of art, such as one 32 × 32 floor block.
Tilesheet A PNG containing many same-size tiles.
Tileset A Tiled .tsx file that tells Tiled how to cut and use a tilesheet.
Layer A named drawing/object surface inside a Tiled map. Layers have specific toolkit jobs.
Template A ready-made .tx object, such as enemy, checkpoint, or solid_box.
Property A setting attached to a map, layer, or object in Tiled's Properties panel.
Export Tiled creates the .lua and .tilemap files that the Defold tools consume.
Editor script A command added to Defold's Project menu. You click it; you do not write it.
Collection/factory Generated Defold resources used to load a playable room.
Layout Editor The in-game tool for positioning rooms and snapping matching doors.
Source A file you own and edit, such as .tmx, .tsx, PNG, WAV, or commented config.
Generated A file written by toolkit commands. Regenerate it instead of hand-editing it.

2. Install And Open The Toolkit#

Install the required versions#

  • Install Defold 1.14.0 from its release page, https://github.com/defold/defold/releases/tag/1.14.0. Later 1.14.x hotfixes are fine. (https://defold.com/download/ always offers the newest Defold, which may be a later version than this toolkit supports.)
  • Install Tiled 1.12.2, or a verified compatible Tiled 1.12.x build, from https://github.com/mapeditor/tiled/releases/tag/v1.12.2 or https://www.mapeditor.org/.

Put the toolkit where you will keep it#

Extract the entire toolkit zip to a writable folder, such as Documents/MyGame_Toolkit. Do not work inside the zip viewer.

No separate toolkit installation is needed after extraction. Keep your Tiled maps in their own folder outside the toolkit, such as Documents/Tiled_worlds.

Windows is the verified beta platform. macOS and Linux use the same steps but remain experimental.

  • Every platform: keep each map's Tile Layer Format at CSV. Rooms made with new_room_blank or Start a New World... already use it; for other maps, change it in Tiled's map properties. Compressed tile layer data needs Python 3 installed, and Zstandard compression is not supported.
  • macOS: install the Defold download matching your Mac (arm64 for Apple Silicon or x86_64 for Intel).
  • Linux: the verified target is an x86_64 glibc distribution, with Ubuntu 22.04 or later as the reference. Use Tiled's AppImage or a normal distribution package; Flatpak/Snap builds may use sandboxed paths and permissions and are not yet part of the verified setup. Install ImageMagick (sudo apt install imagemagick on Ubuntu) if you author picture objects or breakable background tiles from your own sheet.
Expected result: The toolkit folder contains game.project, MVTK.tiled-project, START_HERE.txt, START_HERE.html, developer/, mvtk/, tiled/, and docs/. START_HERE.html shows a picture of every set-up step.

Open Defold and set up the toolkit#

  1. Start Defold.
  2. Click Open Project.
  3. Select the toolkit's root game.project.
  4. Wait until dependency loading and file indexing finish.
  5. Choose Project ▸ Set Up This Toolkit. Click Choose Maps Folder... and pick the folder for your Tiled worlds (create one if needed), or click Set Up Without Folder. If no maps folder is listed yet, running Set Up after Start a New World... in Tiled offers the worlds folder you picked; click Set Up. If it asks instead, click Choose Maps Folder... and pick that same folder (the folder that holds your world folder, not the world folder itself). To change an already listed folder, click Change Maps Folder....

Set Up writes only inside the toolkit folder: it records where the toolkit is, lists your maps folder in Tiled's Project panel, and writes WHERE_THINGS_ARE.txt with the paths you open and export to. Listing the maps folder only makes it easy to find in Tiled; it does not import or export any maps. If Tiled already has the project open, open it again to show the new folder. Run Set Up again after moving or copying the toolkit folder.

Expected result: Defold's Assets pane shows developer, mvtk, and tiled, without a red error popup, and the toolkit folder contains WHERE_THINGS_ARE.txt. Open this HTML guide from your toolkit folder; documentation is excluded from Defold's asset loading.

The Assets pane is the project file tree. The Outline and Properties panes show the selected Defold resource; beginners rarely need them during room authoring. The Console at the bottom shows editor-command, validation, and game output. Keep it visible and treat the first red [ERROR] as the useful starting point when something fails. The toolkit commands used in this guide are under Defold's top Project menu.

Open Tiled#

  1. Start Tiled.
  2. Choose Edit ▸ Preferences... (on macOS it is in the Tiled menu) and click the Plugins tab.
  3. Tick defold and lua, then close the window. Tiled lists them by file name: defold.dll and lua.dll on Windows, libdefold.so and liblua.so on Linux. Every room export writes its .tilemap and .lua through these two plugins; defoldcollection is not needed. Tiled remembers the setting.
  4. Choose File ▸ Open File or Project.... (Tiled 1.12 has no Project ▸ Open Project item.)
  5. Open the toolkit folder, set the file type list at the bottom right to **Tiled Projects (\*.tiled-project)**, and open the root MVTK.tiled-project, not an individual room.
  6. If Tiled shows a yellow bar at the top right saying the project contains scripted extensions, click Enable Extensions. No bar appears when you enabled them before, or when the commands are installed in Tiled itself (see the optional step below).
Expected result: Tiled's File menu contains new_room_blank, Export Current Room, Export All Maps and Tiled World, and Start a New World..., and the Templates panel shows toolkit categories. The maps folder you chose in Defold appears in the Project panel.

Tiled exports to the toolkit whose MVTK.tiled-project is open. To work in another toolkit copy, open that copy's MVTK.tiled-project.

Then take one of these routes:

  • Your own game: first create a tileset for your art (section 3). It fixes your tile size and holds the collision shapes. Then File ▸ Start a New World... asks for a name, the first room's size and that tile size, and creates a world folder with one blank room in your maps folder. That room is not playable yet: section 4 uses it as your start room, adds two more rooms, then exports, prepares and plays them.
  • A sample pack (a separate download): unzip it outside the toolkit folder and follow the START_HERE.txt inside the pack instead. It starts from a fresh toolkit, one per pack. You copy the pack's developer folder into the toolkit by hand (with Defold closed, because it replaces some of the toolkit's settings and art), then open the pack's .world with File ▸ Open File or Project... where you unzipped it, exactly like a world of your own.

If the Templates panel is hidden, enable it from Tiled's View ▸ Views and Toolbars menu. If the toolkit File commands are absent, see Tiled toolkit menus or templates are missing.

Optional: the Tiled commands outside the toolkit project#

You do not need this when you open MVTK.tiled-project as described above. To also get the export commands when you open a room without the toolkit project, install them into Tiled's own extensions folder from the toolkit folder you work in:

  • Windows: run tools\set_tiled_export_path.bat.
  • macOS/Linux: in a terminal in the toolkit folder, run sh tools/set_tiled_export_path.sh.

Exports from rooms opened that way go to the toolkit where you last ran it.

Run one sanity build#

In Defold, choose Project ▸ Build or press Ctrl+B on Windows/Linux or Cmd+B on macOS. The sample project should open at a title screen containing Play Game and Layout Editor. Player preferences are in Settings in the pause menu. Stop the game before editing or running editor commands.

Stop and fix: If the initial untouched project does not build, solve that installation problem before authoring rooms. Record the first red Console error; later errors are often consequences of the first one.

Starting over#

The toolkit release starts empty. To clear an existing project, use Project ▸ Reset Project to Empty (destructive) only when you intend to remove imported content, generated rooms, layout, music and saved settings. The command checks external originals and backs up removed content under developer/.trash/ before restoring the empty-project baseline.

3. Create Your First Tileset#

Choose the art and its real tile size before tuning Game Settings. Imported art establishes the project tile size.

Pick a simple first tilesheet#

Start with one PNG whose tiles are all the same size. Common sizes are 16 × 16, 32 × 32, or 64 × 64 pixels, but new_room_blank accepts any positive size. Square tiles are the safest beginner path because some validation and gameplay assumptions warn about non-square art.

You can use your own art or properly licensed third-party art. Keep the license and attribution information with your project.

Create the external .tsx#

In Tiled:

  1. Choose File ▸ New ▸ New Tileset….
  2. Choose Based on Tileset Image.
  3. Browse to the tilesheet PNG.
  4. Enter the PNG's exact Tile Width and Tile Height.
  5. Leave margin and spacing at zero unless the art pack explicitly uses them.
  6. Save the tileset as an external .tsx beside your source art or in your authoring folder.
Expected result: A Tileset editor opens and displays individual selectable tiles rather than one undivided image.

Import single images (Collection of Images tileset)#

Use this when some of your art is separate PNG files — one file per prop, decoration, or background piece — rather than packed into one gridded sheet. Tiled calls this a Collection of Images tileset, and the toolkit imports each image for you.

  1. In Tiled, choose File ▸ New ▸ New Tileset….
  2. Set Type to Collection of Images (instead of Based on Tileset Image).
  3. Name the tileset and save it as an external .tsx beside your art or in your authoring folder.
  4. With the tileset open in the Tileset editor, click the Add Tiles (+) button and select one or more PNGs. Each image becomes one tile you can place. The images may be different sizes.
  5. Save the .tsx with Ctrl+S.

Add this tileset to a room the same way as a gridded one — Map ▸ Add External Tileset…. Select the art/background object layer, select an image in the Tilesets panel, choose the Insert Tile tool (T), and click the canvas to place the image as a tile object. Do not paint collection images onto art/environment; that is a tile layer reserved for the room's primary gridded tilesheet.

When you run Export Current Room, the toolkit copies every image in the collection into developer/assets/tiled/backgrounds/ and relinks the exported room and tileset to those project-local copies. Prepare & Check then consumes the localized assets. You do not move the files yourself.

Important: A room's painted tile layers still use one primary gridded tilesheet for its floors and walls (see the collision note below). A Collection of Images tileset, image layers, and image-collection object art are additional art that coexists with that primary sheet — they are not a replacement for it, and single images are not where you paint the solid collision layer.

For keys, save points, chests, NPCs and other gameplay objects, use the Tiled object artwork workflow. Draw the interaction area with the rectangle template and link collection-image objects using owner_ref, or place a single image object with its own behavior. That guide also covers catalog artwork for drops, optional state images, and interaction particles.

Add tile collision shapes#

Collision is not inferred from tile numbers or visible pixels.

  1. Open the external tileset for editing.
  2. Select a tile that should be solid.
  3. In the Tileset editor, switch to Tile Collision Editor. If that view is hidden, enable it from View ▸ Views and Toolbars while the .tsx is open.
  4. Choose the rectangle or polygon tool and draw around the solid part of the tile.
  5. Repeat for every solid tile you plan to paint.
  6. Save the .tsx with Ctrl+S.

The toolkit exporter rejects unsaved referenced tilesets because exporting stale collision would produce a room that looks correct but plays incorrectly.

For simple invisible blocks or slopes, you may instead place the solid_box or solid_slope template later. Those are object-based collision shapes.

4. Build A Three-Room Starter World In Tiled#

This walkthrough makes three horizontal rooms:

start_room  --right/left--  middle_room  --right/left--  goal_room

Create start_room#

You need the tileset from section 3 before you paint. Make it first if you skipped that section.

If you used File ▸ Start a New World..., its blank room rooms/<name>_01.tmx is your start room and is already open. Do not create another one: skip to Add your external tileset to the room, and read <name>_01 wherever this walkthrough says start_room.

Otherwise, create the start room now:

  1. In Tiled, choose File ▸ new_room_blank.
  2. Enter a room size in tiles, such as 40x23.
  3. Enter your tilesheet's pixel tile size, such as 32 or 32x32.
  4. Save the map as start_room.tmx in your maps folder.

Save originals outside the Defold project, on any accessible drive. The folders under developer/assets/ contain disposable exported copies. Export rejects original maps, tilesets, images, and file-property assets inside the project.

Use a simple filename matching this pattern:

[A-Za-z0-9_][A-Za-z0-9_-]*

That means letters, digits, or underscore first; letters, digits, underscore, or hyphen afterward. Avoid spaces for beginner projects.

Expected result: Tiled creates a map with top-level bounds, grapple, solid, and templates layers; an exit group containing door_left, door_right, door_top, and door_bottom; and an art group containing the visual layers including environment.

Do not rename or remove the generated structural layers.

Add your external tileset to the room#

With start_room.tmx open, choose Map ▸ Add External Tileset… and select the .tsx you created. The exact wording can vary slightly across Tiled 1.12.x, but the result must be the external tileset visible in the room's Tilesets panel.

Know the Tiled workspace#

Before painting, identify these five areas:

Area What it is for
Center canvas The room you paint and the objects you position.
Layers panel Selects whether you are painting art, bounds, collision, doors, or placing templates. Always check the selected layer before editing.
Tilesets panel Shows tiles from the external .tsx; click a tile here before painting the canvas.
Templates panel Holds the ready-made gameplay objects you drag onto the top-level templates layer.
Properties panel Shows settings for the selected map, layer, tile, or template object. Click the item first, then edit its property here.

Use View ▸ Views and Toolbars to restore a hidden panel. The most common beginner mistake is painting or dragging while the wrong layer is selected, so confirm the Layers highlight before every new kind of edit.

Room layers at a glance#

new_room_blank creates these layers for you. Do not rename or delete them.

Layer Job
bounds The room's outer footprint. Paint a closed one-tile ring; keep it unbroken even at doorways.
solid Collision. Paint only tiles that have Tile Collision Editor shapes and should block the player.
grapple Hook tags. Paint the ceiling's bottom rock row or hanging anchor cells; give them visible art. The tags are hidden in game and bake into editable Grapple Surface gameobjects.
art/environment Visible floors, walls, and decoration. Add more art layers for foreground/background as needed.
exit/door_left, door_right, door_top, door_bottom Exit markers. One painted tile shows the Layout Editor where this room connects.
templates (top level) Where you drag ready-made objects — player start, enemies, collectibles, hazards, NPCs, and so on.

Painting on the wrong layer is the most common first-world mistake. Confirm the highlighted layer in the Layers panel before each new kind of edit.

Paint visible art, bounds, and collision#

Paint in this order so each layer has one clear job:

  1. Select art/environment and paint the visible floor, walls, and decoration.
  2. Select bounds and paint a one-tile outer room outline.
  3. Select solid and paint only tiles that have Tile Collision Editor shapes and should block the player.
  4. If the room uses grappling, paint a grapple layer where the hook may catch. Use visible hooks, rings or rails on the art layers to mark these spots. See Grappling for tagged surfaces and the Game Settings Grapple tab.

Keep foreground decoration on the appropriate foreground art layer so it does not accidentally become collision.

Expected result: The room looks like a small platforming space, bounds outlines it, and solid contains only collision-bearing tiles.

Let painted Tiled art replace a template placeholder#

Player starts, checkpoints, and save points are invisible gameplay markers. Paint any artwork for them on Tiled's visible art layers. They never add a Defold placeholder sprite, even when an older map still has use_defold_sprite=true.

Some gameplay templates include a simple Defold sprite so the object remains visible before final art exists. When you paint the finished object art on a visible Tiled tile layer, select the template object and set use_defold_sprite=false. Prepare & Check then keeps the object's scripts, collision, effects, and behavior while omitting only its embedded Defold component named sprite.

Leave use_defold_sprite=true when the Defold prefab should draw the object. Platforms and volumes that normally expect painted art—one-way platforms, gates, breakable walls, pressure plates, water volumes, bounce pads, conveyors, timed doors, and wall-jump surfaces—default to false; the other supported templates default to true. Water distortion remains available because it is a separate effect, not the placeholder sprite.

After changing the property, save and export the room, then run Prepare & Check. Validation warns when the placeholder is disabled but no visible non-control tile is painted beneath the object.

For example, to replace a teleporter placeholder, paint the teleporter art on a visible tile layer directly beneath the teleporter template object, set that object's use_defold_sprite property to false, export, and run the three commands above. Set the property back to true whenever you want the prefab's built-in teleporter sprite again.

Place the player start#

  1. Select the visible top-level templates object layer.
  2. In the Templates panel, open Navigation.
  3. Drag player_start into a safe open point above the floor.
  4. Leave its defaults (spawn_type=player, is_default=true, and checkpoint_id=start) for this first world.

For the Layout Editor route, one player_start is enough to identify the starting room. Export All Maps and Tiled World also needs the boolean map property is_starting_room=true on exactly one room of the world: Start a New World... sets it on its first room; for another world, add it in the start room's Map Properties. Avoid multiple starting rooms because selection can then depend on ordering or saved state.

Paint the first door marker#

Select exit/door_right and paint at least one tile where the right exit should connect. Door connectivity comes from these painted door_* layers, not from a door template and not from the solid layer.

Leave a real opening in visible/collision art so the player can pass through the edge. A painted door marker tells Layout Editor where rooms connect; it does not automatically carve a hole through your wall art.

Add optional room music#

  1. Choose Map ▸ Map Properties.
  2. Find or add music as a file property.
  3. Select an Ogg Vorbis .ogg or WAV .wav file.

The file may be outside the toolkit. Prepare & Check copies and registers it. Empty music means “keep the current track.” Adjacent rooms using the same file continue the song instead of restarting it.

Defold does not use MP3 for this workflow. Convert MP3, FLAC, M4A, AAC, or Opus to .ogg or .wav first. For example:

ffmpeg -i song.mp3 song.ogg

The biome property controls visual/environment metadata; it does not choose the room's music.

Save and export start_room#

  1. Save the map with Ctrl+S.
  2. Save the .tsx too if you edited collision.
  3. Choose File ▸ Export Current Room.
  4. Read the export summary and correct any error before continuing.
Expected result: The project contains developer/assets/tiled/maps/start_room.lua and developer/assets/tiled/maps/start_room.tilemap.

Create middle_room#

Rooms two and three are new maps. Create each with File ▸ new_room_blank (also when your first room came from Start a New World) and save it in the same folder as the start room:

  1. Use the same tile size and add the same external .tsx.
  2. Paint environment, bounds, and solid collision.
  3. Do not add another player_start.
  4. Paint one tile on door_left and one on door_right.
  5. Add one easy recipe object, such as checkpoint, collectible, enemy, or sign, on the top-level templates layer.
  6. Save as middle_room.tmx and export it.

Create goal_room#

Repeat once more:

  1. Use the same tile size and add the same external .tsx.
  2. Paint environment, bounds, and collision.
  3. Paint one door_left marker.
  4. Add a save_point, chest, or other simple reward.
  5. Save as goal_room.tmx and export it.
Expected result: All three rooms have matching horizontal doors: start_room right ↔ middle_room left, and middle_room right ↔ goal_room left.
Started with Start a New World? New rooms are not added to its world automatically, and this walkthrough does not need them there: you export each room and arrange the rooms in the Layout Editor (section 7). To keep every room in the Tiled world instead, open the start room, select the World Tool on Tiled's toolbar, click Add another map to the current world, choose the new room, and drag it beside its neighbor so the doors line up. Then follow Use a world already arranged in Tiled.

Author rooms outside the toolkit folder#

Keep original .tmx, .tsx, .world, tilesheet PNG, image layers, and music in your own art/level folder outside the Defold project, including on another drive.

7. Arrange And Publish The World In Layout Editor#

Use a world already arranged in Tiled#

Layout Editor is optional when you arrange the rooms in a saved Tiled .world.

  1. Open the world in Tiled. Use finite orthogonal TMX maps with the project's tile dimensions, matching painted door openings, and exactly one starting room: the room with the player_start, marked with the boolean map property is_starting_room=true (Start a New World... marks its first room).
  2. Choose File → Export All Maps and Tiled World. This saves modified member maps, referenced tilesets and the world, exports every member through the normal Lua/tilemap exporter, and records their placements. A canceled save or failed batch keeps the previous exported generation.
  3. Stop the game in Defold. After installing toolkit changes, restart Defold to clear cached Lua modules, then Project → Reload Editor Scripts.
  4. Run Project → Prepare & Check. On the first import choose Use Tiled World Layout. Preparation imports assets, creates editable room collections, checks connections and elevators, and publishes the layout and minimap together.
  5. Build and choose Play Game with an empty save slot. No Layout Editor export is needed.

World name and room defaults#

Open MVTK.tiled-project with its extensions enabled, then create or open a world. Open World Properties from Tiled’s world controls: the five toolkit fields are added automatically, preserving any existing choices. There is no setup command and no code editing. Save the world after editing; world export also saves it. This applies only inside the toolkit project.

Property Type / meaning
world_name String. Displayed above the full world map. Empty keeps World Map. It does not rename the game or change save identity.
default_biome biomes dropdown. Used when a room's biome is missing, empty, or inherit.
default_music music_tracks dropdown. Synced track ID used when room music is missing, empty, or inherit. Prepare & Check populates this list.
default_ambience ambient_sounds dropdown. Ambient loop independent of music; must have a configured sound component. Room ambient_sound overrides it.

Explicit room selections win. New blank rooms use inherit for their biome; existing rooms keep their choices, including default. To inherit music, clear the room's music value or select inherit. New world defaults start at inherit, preserving existing room behavior. Once you select a track or none for default_music, an explicit room none means silence. Ambient none means no world/room ambient loop; placed sound objects remain independent. Music triggers temporarily override the selected track. A trigger with stop_on_exit and no explicit exit track restores the room/world music. Room-to-room ambient changes stop the previous loop, and rooms sharing a loop keep it playing. Sound playback still requires your configured audio assets.

9. Common Creator Recipes#

All placed objects go on the visible top-level templates layer unless a recipe says otherwise. Select a template instance to edit its properties in Tiled's Properties panel. Leave mvtk_template_version unchanged.

Understand grouped template properties#

Most templates keep the property that identifies the object, such as enemy_type, plus its required ID at the top level. Less-common settings are organized into one-level collapsible groups such as movement_and_attacks, stats, interaction, or feedback_and_visuals. Expand only the group you need; a collapsed group still contributes its template defaults.

Six tiny placement templates intentionally stay flat because grouping would add more clicks than clarity: solid_box.tx, solid_slope.tx, grapple_box.tx, grapple_slope.tx, one_way_platform.tx, and player_start.tx.

Newly placed templates already include these grouped properties. No upgrade step is needed. Maps made before template version 2.7 can keep their legacy flat overrides; export, validation, Prepare & Check, and runtime accept both layouts. Avoid manually keeping both spellings of the same field on one object.

Replace the player sprite#

The beginner-safe rule is to keep the existing animation IDs and replace art, not controller code.

The optional source-driven importer uses:

  • Template: developer/assets/source/player_template/Mannequin/, a colour-coded figure in every pose the game uses
  • Importer: developer/tools/generate_player_sprite_frames.py
  • Generated frames: developer/assets/sprites/player/
  • Generated atlas: developer/assets/atlas/player.atlas

Install Pillow for the Python interpreter you use. Copy the Mannequin folder beside itself, for example as MyPlayer, replace its sheets with your art (same folders, file names and layout), then run:

py developer/tools/generate_player_sprite_frames.py --source "developer/assets/source/player_template/MyPlayer"

The bundled player art is the Wayfarer pack in developer/assets/source/player_template/Wayfarer/. It is drawn by developer/tools/generate_player_model_pack.py; run py developer/tools/generate_player_model_pack.py to redraw it and import it again. A pack can also add the optional sheets Swim/, Swim Idle/, Ledge Hang/, Grapple/, and Climb Idle (facing back of player)/; when one is missing, the importer uses stand-in frames instead. Ladder climbing always uses the Climb (facing back of player) sheet.

Export frames at their intended in-game pixel size and leave Player Size at 1.00 (100%). The bundled template packs use 192 × 192 frames with crisp 4 × 4 pixel blocks; in Aseprite, export the original 48 × 48 drawings at 400%. The importer copies these frames at 1:1 by default, so one image pixel is one world pixel at Player Size 1.00.

Project ▸ Game Settings… ▸ Player art can import another PNG sheet or a sequence of frames. Leave displayed width and height at 0 to use the frame dimensions. Explicit dimensions that differ from the frame stretch the model; the preview shows a note. Export frames at in-game size to keep the art at 1:1.

To import a pack without changing the sprite's in-game size and offset, add --source <pack folder> --keep-geometry. A pack.json in the pack folder can set "keep_geometry": true and other import settings; see the importer's header comment.

Core player animation IDs include idle, walk, run, jump, fall, land, crouch, slide, dash, air_dash, wall_slide, wall_cling, attack, attack_alt, shoot, hurt, die, and spawn. Optional imported IDs can be remapped through Config.player.animation_overrides in the commented developer/config/game_config.lua; do not edit mvtk/animation.

The importer's --target-height and --upscale options are explicit resampling options for art drawn at another size. Prefer exporting at the intended in-game size. Player Size below stretches the existing art for size experiments.

Resize the player#

Each player model's files define its normal in-game size. Keep Player Size at 1.00 (100%) for art exported at that size. Change the single player_scale value to experiment with a larger or smaller body and model.

  1. Stop the game and open Project ▸ Game Settings… ▸ Player. Set Player size (1 = 100%) between 1/7 and 8 using its numeric field.
  2. Leave scale_movement = true to scale speeds, jump height, gravity, and traversal ranges with the body. Set it to false when you want to retune those movement values by hand.
  3. Click Save in Game Settings to write the scale and rebake the player sprite size and all player collision resources. If you edited the config file directly, stop the game and run Project ▸ Prepare & Check instead.
  4. Run a normal Build, then use a fresh playtest to check floors, walls, ladders, one-way platforms, low roll/slide gaps, melee reach, and jump feel.

Values such as collider halves, speeds, jump height, gravity, and ranges in player_settings.lua and in the Game Settings fields are world-pixel numbers at Player Size 1.00. With the scale_movement = true default, runtime applies player_scale exactly once to movement and traversal values. Changing the config value does not require Reload Editor Scripts, but direct config edits still require the explicit Prepare & Check bake.

Recommended: link the original art from Tiled. Keep one snake_case folder per skin outside the Defold project, for example enemies/moss_bug/ beside your original maps.

Tune enemy movement and attacks in Tiled#

Select the placed enemy and start with enemy_type, the first custom property. It chooses the art, stats, animations, movement, and attacks supplied by that enemy's preset. In most cases that is the only property you need to change. Expand movement_and_attacks only when this placement should behave differently; the stats, rewards, and tuning groups hold less-common overrides. A group's -1 numeric defaults inherit the selected type instead of replacing it.

The behavior fields are independent per-instance overrides:

  • movement=type_default keeps the selected enemy type's movement.
  • attack_pattern=type_default and attack_pattern2=type_default keep its attacks. Changing only movement no longer removes a preset attack, and changing only an attack no longer stops preset movement.
  • attack_pattern=disabled deliberately removes the inherited attack in that slot while retaining contact damage. If a preset uses two attacks, set both attack slots to disabled. Use stationary when an enemy should stop moving without losing its configured attack.
  • Older exported values none and inherit remain aliases for type_default. Older movement names such as patrol and chase still load, but the explicit choices below make ground/air behavior clearer.

Common movement choices are:

Movement Result
ground_patrol Walks back and forth around its placement point.
ground_patrol_chase Patrols, chases a detected player on the ground, then returns after losing aggro.
ground_chase Chases a detected player horizontally without leaving the ground.
flying_chase Chases in both horizontal and vertical directions.
vertical_patrol Moves up and down around the placement point.
hover Uses the configured aerial hover/patrol range.
flee Moves away from a detected player.
zigzag Moves in a repeating zigzag.
stationary Does not move; configured attacks still run.
ghost_float Uses the ghost's floating follow and close-range rise behavior.

Ground movers stop at drops, and patrollers turn back there. The ledge settings in developer/config/enemy_defaults.lua are measured in tiles of your project's tile size, so they work at any tile size. stop_at_ledges turns the check on. ledge_margin_tiles sets how close the enemy's centre gets to an edge (a quarter tile). ledge_probe_depth_tiles sets how far below the centre it looks for floor; keep it deeper than your tallest enemy's feet. ledge_step_tolerance_tiles lets enemies walk over small steps down (an eighth of a tile). Per enemy type in developer/config/enemy_types.lua, you can set stop_at_ledges, or ledge_margin in pixels for an enemy that is unusually wide or narrow for your tiles. Ground movers never move up or down to follow the floor, so a downhill slope that drops more than the step tolerance within the margin counts as a drop: the enemy stops at the top of it.

Use detection_range to set the aggro radius and chase_speed for the base chase speed in pixels per second. A value of 0 inherits the enemy type's value. A positive chase_speed_mult multiplies the resolved chase speed; 0 inherits the preset multiplier. Keep values proportional to your art scale and test one enemy before applying them to a whole room.

The shipped enemy types are already paired with their intended behavior:

Keep Dash, difficulty and first-use hints#

On Project ▸ Game Settings… ▸ Abilities, Dash unlocks the ground slide-to-run movement. Enable Slide too. Hold the Slide / Air Dash action through the end of a ground slide to continue at Run Speed; release it to return to walking. Air Dash uses that same action while airborne and has its own unlock. The action can be rebound in Settings. Baseline movement tuning lives in developer/config/player_settings.lua, including slide_to_run.

Choose the game's starting difficulty with current in developer/config/difficulty_settings.lua. Its named profiles tune incoming and outgoing damage; normal uses 1.0 for both. Keep those multipliers positive. A placed enemy's Difficulty Override can choose a named profile for that enemy's health and damage; empty inherits its defaults. This is file and Tiled configuration, and is not a Game Settings difficulty control.

Edit developer/config/tutorial_popups.lua for first-use popups. The first_jump, first_dash and opened_map events run on an accepted Jump, Slide / Air Dash or World Map press. Each popup's trigger_flag prevents repeat display and is saved with normal story flags. Use title and body for literal wording, or explicit title_key / body_key for localization; missing translations fall back to the literal text. Mention actions rather than fixed keys so the hint still makes sense after rebinding.

Add a collectible, key, and chest#

  • Place collectible; choose collectible_type and set amount.
  • Place key; choose a key_id such as the key used by your door/gate.
  • Place chest; give it a unique chest_id, set contents such as currency:25, and optionally set locked plus requires_key.

Prepare & Check bakes every placed chest into an editable gameobject in the room collection.

Add an ability pickup and gate#

  1. Place ability_pickup and select the ability it grants.
  2. Place gate where passage should be blocked.
  3. Give the gate a unique gate_id.
  4. Choose a gate_type and set the matching requirement: required_ability, required_key, required_item, or required_action.
  5. Leave persist_unlock=true when the gate should remain open after success.

For a simple physical locked door, use locked_door instead. Set a unique door_id and one of require_ability, require_key, or require_item.

Add checkpoints, save points, and teleporters#

  • checkpoint: set a unique checkpoint_id; touching it changes respawn location.
  • save_point: set a unique save_id; choose whether it heals/restores energy and requires interaction.
  • teleporter: create a pair with unique teleporter_id values and matching pair_id, or set an explicit target_id. Keep IDs exact and case-consistent.

Death and saves#

Death reloads the last saved world and inventory. With Death drop on, the loss is calculated from the restored currency, never from unsaved pickups. The slot immediately records the reduced currency and one recoverable drop; quitting and choosing Continue keeps that penalty. The checkpoint location and other saved items, flags and abilities keep their saved values.

The drop waits at the last safe grounded position in the death room and returns its currency when collected. If no trustworthy safe ground was recorded there, the game waives that death's loss and keeps any earlier drop. Dying again with a valid safe position replaces the previous drop; its old amount is lost. A zero-loss result clears the previous drop.

In developer/config/game_config.lua, progression.death also offers max_loss (0 means no extra cap), drop_lifetime (0 lasts until collection or replacement), drop_pickup_radius in world pixels and drop_sound. The marker follows room streaming and survives a save/load round trip. Collection needs no immediate save: another death before saving restores the reduced currency and drop together. Place save points when you want recovered currency and current progress committed to the slot.

Add hazards, secrets, and breakable walls#

  • hazard: choose hazard_type, damage, interval, and whether it is instant kill or retractable.
  • secret: give it a unique secret_id, choose how it reveals, and optionally set a reward.
  • breakable_wall: give it a unique wall_id, choose health/required ability, and optionally link reveals_secret to a secret ID.
  • timed_door: use for a door controlled by a duration or trigger rather than inventory progression.

Template rectangles define active areas. Resize them in Tiled to cover the intended region.

Add simple traversal#

  • one_way_platform: a passthrough platform area.
  • moving_platform: choose motion type, speed, distance, wait time, and loop mode.
  • elevator + elevator_node: build a persistent vertical cabin that can cross streamed rooms. Follow the dedicated workflow below; this is not a tall single-room moving platform.
  • conveyor: choose direction and speed.
  • crumble_platform: tune crumble and respawn timing.
  • bounce_pad: tune the launch force.
  • ladder: resize the rectangle over the climbable art. If the climb animation looks off-center for your rig, tune climb_offset_x instead of moving the rectangle; it only applies when snap_to_center=true and uses unscaled world pixels.
  • wall_jump_surface: resize over the wall that permits wall behavior.
  • water_volume: resize the region and tune swim, current, damage, drag, and oxygen properties. buoyancy is a 0–1 factor that becomes an upward cap of 0–200 px/s, current_strength is px/s, and water_drag is per-second drift retention (0–1). Swimming requires the swim ability unless game_config.player.swim.require_ability = false.

Place a grapple point or pushable block#

Place Navigation ▸ Grapple Point on the top-level templates object layer for a small hook target. It bakes as an editable static grapple collider, with no script overrides. Pair it with visible anchor art. See Grappling for surfaces, exact shapes and hook-target tuning.

Place Physics ▸ Pushable Block, resize its rectangle and paint its art. Walk against it to push. Hold Interact beside it to grab, then move toward or away to push or pull; release Interact to let go. Set mass and gravity_scale for the body, and move_embedded_tiles to move captured art with it. Use a stable block_id when you need identity; an empty value is generated from the placed object. To hold a pressure plate down, set the plate's allow_world to true so the block's world body can activate it. Both objects become gameobjects in the room collection.

Water & swimming troubleshooting#

On water entry, use the console output to identify the active path: Trigger water gate only (without Water entry swim gate or [WATER] Entity entered water) means a trigger armed no swim state; both gate lines with has_swim=false mean the swim ability is locked and the intended sink-and-lock gate is active; both lines with has_swim=true mean swimming is armed and any remaining issue is movement tuning. Current builds also print [SWIM] armed ... for every source, including bare water triggers; paste that line into a bug report.

For a first game, prefer horizontal/vertical moving platforms. path_name requires a correctly named Tiled polyline path and is an advanced option.

Build an elevator across streamed rooms#

Use one elevator rectangle for the cabin and one elevator_node point for every landing or room-seam waypoint. The cabin is world-owned while moving; adjacent room collections can unload normally once the trip ends.

  1. In the lower/start room, paint the cabin itself on the environment tile layer. Snap its outer edges to the tile grid.
  2. Place the elevator rectangle exactly around those tiles. Set a globally unique elevator_id, such as mine_lift_a, and set start_node_id to the node where this painted cabin begins.
  3. Put an elevator_node point at the cabin floor, horizontally centered on the shaft. Give it the same elevator_id, a unique node_id, node_kind=landing, and stop=bottom.
  4. In the upper room, place the matching centered point with the same elevator_id, another unique node_id, node_kind=landing, and stop=top.
  5. Paint a vertical door opening between each connected room pair. The lower room must connect upward and the upper room downward. Make the opening at least as wide as the cabin plus shaft_clearance. When a pair has multiple openings, the validator selects the opening aligned closest to the shaft.
  6. For a shaft through additional rooms, add a centered node_kind=pass_through / stop=none node in each intermediate room. Keep route nodes strictly bottom-to-top, and do not leave and later re-enter the same room along one route.
  7. Run Prepare & Check, then rescan/connect the rooms in Layout Editor and click Export. Run Prepare & Check once more, then Build so validation uses the final exported room positions and doors.

Prepare & Check validates the route identities and cabin art together, cuts the cabin tiles out of the source room tilemap, and creates a persistent tilemap, collision child, collection, factory, and generated route index. Prepare & Check then resolves that index against the exported layout and rejects non-adjacent rooms, one-way or horizontal links, misaligned shafts, and openings that are too narrow. At runtime the elevator pins the ordered route while travelling, commits room ownership exactly at each door seam, and gives the camera a temporary shaft-scoped focus. It releases both streaming and camera leases on arrival, cancel, player death, reset, or a dead cabin owner.

Hidden elevator and elevator_node objects are excluded, including markers inside a hidden parent group. This is useful for parking an unfinished draft route, but never hide a node that a visible controller names as its start_node_id; Prepare & Check reports that reference as an error. Generated cabin assets live only in reserved _mvtk_elevators/ subdirectories below the generated, collections, and factories folders. Prepare & Check reconciles those folders against the current manifest, so deleting or renaming an elevator does not leave an old cabin factory behind.

Choose activation_mode=on_board for the usual Metroidvania behavior; require_interact=true changes that mode into a button press while the player is aboard. automatic continuously shuttles between the two landings (and, when require_rider=true, only schedules trips while at least one player collider is aboard). trigger_only moves only when its elevator_id or optional trigger_id receives an elevator call. The two-terminal route is always ping-pong. With the persistence defaults enabled, only completed bottom/top landings are saved and restored; an interrupted mid-shaft position is never written to the save.

Keep floor_offset equal to the rectangle height when the walking surface is the cabin's top edge (the 32-pixel template defaults already match). If you resize the cabin vertically, update this value too; use a smaller value only when the walkable floor is intentionally inside the captured art. The co_y_offset and sensor_y_offset fields are fine collision-tuning controls, not substitutes for floor_offset.

The baked landing marker receives elevator_doors_closing, elevator_departed, elevator_incoming, elevator_arrived, elevator_doors_opening, and elevator_trip_completed messages while its room is loaded. Those are extension hooks for a custom animated shaft-door prefab; the elevator templates themselves use the painted shaft opening and do not create or permanently unlock an inventory/ability door.

If generation stops, fix the first reported route error in Tiled. Common causes are an off-grid cabin rectangle, no painted tiles under it, duplicate IDs, missing bottom/top stops, a node that is not at the cabin centerline, a start node in another room, non-reciprocal up/down room links, or a shaft opening narrower than the cabin. Do not hand-edit elevators_generated.lua or any generated cabin resource, including files below _mvtk_elevators/.

Tune climb_offset_x in small 8-16 px steps and keep its absolute value within roughly half the ladder rectangle's width. The player's collision body moves with the offset, so a large value can push it into nearby walls or outside the trigger box; after jumping off, the player must re-enter that box to grab the ladder again. If the rig is off-center on every ladder, fix the art or an animation_overrides setting and reserve this property for individual spots.

Build a compact boss encounter#

The supported boss surface contains exactly five templates:

  1. Place a boss_arena rectangle over the fight space. Give it an arena_id, such as guardian_arena, and choose camera/locking behavior.
  2. Place one boss point inside. Give it a boss_id, such as guardian, and set its arena_id to guardian_arena.
  3. Place boss_phase point objects for authored boss phases. Give each the same boss_id/arena_id, set phase, health range, attacks, and movement profile.
  4. Optionally place boss_phase_trigger rectangles when entering an area should force a boss phase.
  5. Optionally place boss_weak_point rectangles and link them with the same boss_id.

Use consistent IDs across every object. Start with one arena, one boss, and one boss phase. Add triggers/weak points only after the basic encounter validates. boss_arena supplies the arena rectangle and entry-lock behavior; do not look for old arena-boundary, hazard-spawner, or add-spawner templates.

Boss movement and charge difficulty is authored directly on those placed objects:

  • On boss, expand attack_tuning to set the base chase_speed, charge_speed, charge_distance, charge_telegraph_time, charge_duration, charge_cooldown, and charge_recovery.
  • On boss_phase, use attack_sequence for the boss phase attack list, attack interval/range, and optional charge overrides. Use movement for the boss phase chase_speed and speed_multiplier. A boss phase override wins over the boss value; the speed multiplier is then applied to movement and charge speed.
  • On boss_arena, expand encounter and set charge_edge_padding to keep a charge endpoint away from the rectangle's left and right edges.

The optional tuning fields default to -1, meaning inherit. Leave them at -1 when that object should use its boss, preset, or attack-pattern value. After changing any of these properties, save the TMX, run File ▸ Export Current Room, and run Project ▸ Prepare & Check in Defold.

Leave the map's room-wide room_zone at exploration or platforming. Do not select the old boss_arena room preset: it can lock the camera from the room's entry position. The placed boss_arena rectangle is the supported owner of the fight's lock and camera behavior.

Understand precedence#

Maps begin hidden and uncover the area shown by the gameplay camera, including an entire room when it fits on screen. Scrolling and zoom changes reveal newly visible cells even while the player stands still. A visible neighboring room can appear on the map before the player enters it; preloading alone does not reveal terrain, and hidden-secret rules still apply. Map stations reveal their configured areas, and discovery is saved independently in each slot. The default mode = "nearby" also reveals an optional radius around the player; mode = "room" reveals the whole current room on entry, even beyond the screen. The commented map_discovery_settings.lua controls that extra radius, cell size, and edge_softness: the world-pixel radius that rounds and feathers the fog on both maps. Increase it for softer edges, or set it to 0 for hard edges; it does not change saved exploration or marker visibility. Tiled markers explicitly marked visible_from_start can still point toward unknown areas.

Set a unique, permanent game_id in persistence_settings.lua before releasing your game. When left empty, the title in game.project determines the save directory, so changing that title changes the save location. Old shared toolkit saves remain untouched; start with a fresh slot after upgrading. See the configuration handbook for preserving a verified older save.

Controls and input#

Defold's editable input map is developer/input/game.input_binding. Open it in the Defold editor to add or change keyboard, mouse, touch, or gamepad triggers. The current physical-action allowlist and starter high-level mappings live in the inputs and actions tables in developer/config/default_bindings.lua. Physical IDs are device-separated: keyboard inputs use key_*, and standard controller inputs use gamepad_*.

By default, pressing M or R3 (the right thumbstick click) cycles the gameplay map display through no map → minimap panel → full-screen map → no map. The physical key_m and gamepad_rstick_click actions are mapped to MINIMAP_TOGGLE; the separate interactive world-map action remains independently rebindable.

This toolkit targets Defold 1.14.0's built-in SDL controller database. It tracks controller connect/disconnect events and uses the first mapped controller for the single player; unmapped devices remain visible in diagnostics but cannot claim gameplay, and unplugging the active pad clears its held input and selects the next mapped controller. Left- and right-stick direction actions preserve analog strength. game.project owns the one hardware deadzone, so do not add another deadzone in player settings or a project .gamepads compatibility file.

Runtime remaps use a versioned current-only save. When the binding schema changes, incompatible older remap data is ignored and current defaults are used; there is no legacy alias migration layer. Controller remapping preserves that action's keyboard inputs, accepts only real controller events, and moves a controller button away from any previous high-level action.

Keep action IDs synchronized across both files and any creator-facing config or GUI that listens for them. For example, renaming gamepad_lstick_left in only the input binding does not rename the action expected by the player controller. Prefer changing the key/button attached to an existing action. Add a new action ID only when the corresponding feature already knows how to consume it.

Build after changing bindings. Use the in-game pause menu’s Settings and rebind UI for player preferences; edit the Defold binding resource when you are changing the project's available default actions.

13. Troubleshooting By Stage#

Installation or first Defold build fails#

  • Confirm Defold is 1.14.0 or a later 1.14.x hotfix and the toolkit was fully extracted/installed.
  • Keep the project in a writable folder; avoid protected system directories.
  • Wait for Defold dependencies to finish loading.
  • Read the first red Console error, not only the last one.
  • Run Project ▸ Set Up This Toolkit again, especially after moving or copying the toolkit folder.

A property type error appears after updating the toolkit#

After updating, run Reload Editor Scripts → Prepare & Check → Build. Prepare & Check rebuilds the room collections with the current property types.

A Console error The property '<name>' must be of type 'string' means a room or prefab still stores the old hash type. Run Prepare & Check. If the message names one of your own prefabs, re-enter that value in the Defold Properties panel, save the prefab, and Build again.

Tiled toolkit menus or templates are missing#

  • Open MVTK.tiled-project with File ▸ Open File or Project..., not only a .tmx.
  • Click Enable Extensions in the yellow bar at the top right. If you dismissed it, close the project and open it again.
  • Check Tiled's View ▸ Views and Toolbars ▸ Console for an error that names a file in tiled/extensions.
  • Confirm File ▸ new_room_blank, File ▸ Export Current Room, File ▸ Export All Maps and Tiled World and File ▸ Start a New World... appear.

Export says "Required exporters not found"#

Tiled's defold or lua plugin is off; the message lists which one (false). Choose Edit ▸ Preferences..., click the Plugins tab, tick defold and lua (defold.dll and lua.dll on Windows, libdefold.so and liblua.so on Linux), close the window and export again.

Tiled cannot detect the project root, or exports go to another toolkit#

Exports go to the toolkit whose MVTK.tiled-project is open. Open the MVTK.tiled-project in the toolkit folder you want (the folder that holds game.project), click Enable Extensions if Tiled asks, and export again. WHERE_THINGS_ARE.txt in each toolkit folder lists that toolkit's paths.

Export says a tileset is unsaved or missing#

  • Save the room and every external .tsx.
  • Confirm the .tsx still points to the original tilesheet image.
  • For external authoring, keep editing the original, not the localized project copy.
  • Re-export after fixing the source path.

Tiles are invisible or use the wrong art#

  • Confirm the room uses one primary tilesheet for painted tile layers.
  • Verify Tile Width/Height match the actual image grid.
  • Re-export, then run Prepare & Check.
  • Check developer/assets/tilesheets/ for the localized primary image.
  • Read Prepare & Check warnings about tilesource resolution.

The player falls through floors or hits invisible walls#

  • Open the .tsx and confirm solid tiles have Tile Collision Editor shapes.
  • Save the .tsx, not only the room.
  • Paint collision tiles on solid, not just environment.
  • Remove accidental collision shapes from decorative tiles.
  • Alternatively use solid_box/solid_slope, then export and rebuild.

Prepare & Check fails#

  • Stop the running game first.
  • Run Reload Editor Scripts and try the exact five-command sequence again.
  • Fix the first error in Defold Console.
  • Open debug_output.txt when Prepare & Check points there.
  • Do not patch generated collections to hide the source error.

A room is missing from Layout Editor#

  • Confirm both <room>.lua and <room>.tilemap exist.
  • Run Prepare & Check.
  • Confirm developer/rooms/collections/<room>.collection exists after generation.
  • Open Layout Editor and click Rescan Rooms.
  • Use a simple unique room filename.

Rooms do not snap or transitions fail#

  • Paint at least one tile on each intended door_* layer.
  • Connect right ↔ left or top ↔ bottom.
  • Leave a physical opening in art/collision at the marker.
  • Export both rooms, rebuild, Rescan Rooms, and place them again.
  • Click Layout Editor Export after snapping.

The wrong room or position loads#

  • Keep exactly one intended player_start for a simple project.
  • Avoid multiple maps marked is_starting_room=true.
  • Export/rebuild after changing the start.
  • Use an empty save slot; an existing checkpoint may override the new start.
  • Export the layout before Play Game.

A Tiled object does not appear#

  • Put it on the visible top-level templates layer.
  • Use a shipped .tx instance rather than drawing an untyped rectangle.
  • Keep mvtk_template_version unchanged.
  • Fill required IDs/dropdowns and avoid duplicate unique IDs.
  • Export, Prepare & Check, and inspect the generated collection in Defold.

Enemy art or animations are missing#

  • Confirm a linked skin contains idle_01.png; a directly supplied project folder can also use idle.png.
  • Use individual PNG frames, not one strip/sheet.
  • Use recognized state prefixes and consistent frame dimensions.
  • For linked art, confirm art points to an existing frame outside the Defold project, named <state>_<number>.png. Export again after changing the original frames.
  • For project folders, leave art empty and choose the synced folder ID in enemy_type.
  • Run Prepare & Check after Defold finishes importing files, then Build.
  • Restart Tiled after updating the toolkit's exporter or templates.

Music or ambience is silent#

  • Use .ogg or .wav, not MP3.
  • Set map music as a file property for room-wide music.
  • Save/export the room, then run Prepare & Check.
  • Check the Console for an unsupported extension or missing source path.
  • For music_trigger/ambience_zone, choose an ID already registered by sync/config.

Boss arena or phases do not link#

  • Give boss, boss_arena, and boss_phase matching boss_id/arena_id values.
  • Start with a single boss phase and a known boss_type.
  • Keep the boss point inside the arena rectangle.
  • Remove optional boss phase triggers/weak points until the base fight validates.
  • Re-export and Prepare & Check after every boss-object change.

Layout changes appear in editor but not Play Game#

Click Layout Editor Export and wait for completion. Menu and placement autosave do not replace the published runtime layout.

  • Reload Editor Scripts, Prepare & Check, and Build all succeed.
  • Layout Editor Export succeeds after the final placement.
  • A new empty save starts in the intended room.

Create a standalone release project#

Project ▸ Export Game is different from Build and from Layout Editor Export. It packages the published room/layout revision into a standalone Defold project under export/. It does not regenerate rooms. Stale or unpublished changes must be prepared, built, and published before exporting.

Before using it:

  1. Finish the normal Tiled export and five-command Defold sequence.
  2. Export the final Layout Editor layout.
  3. Playtest with a clean save.
  4. Run Project ▸ Export Game.
  5. Open export/game.project as a separate Defold project, run Project ▸ Fetch Libraries, then build/test it.
  6. Use Defold's normal bundle command for the target platform only after that standalone project passes.

Do not confuse export/ with your editable source. Regenerate it from the main toolkit project.

The standalone title screen shows your game name and opens save-slot selection; Game Settings and Layout Editor stay in the source project. Export includes published room data, referenced runtime art/resources, configuration, and creator-declared custom/bundle resources. By default, source art, Tiled originals, authoring reports, unused room resources, dependency caches, and build folders are omitted. export/EXPORT_MANIFEST.txt lists each included file and why it was selected. Keep dynamically selected custom data in game.project's custom_resources or bundle_resources so it is included explicitly. Custom stream paths use the runtime's configuration resolver; export reports an error if their Lua configuration cannot be evaluated instead of using other paths.

Export writes and verifies a staging project before replacing export/. A failed write or publication preserves the previous export; retrying recovers an interrupted directory swap. Changes made directly in export/ are replaced by the next export.

Architecture and ownership#

  • Tiled .tmx/.tsx plus source art are authoring truth.
  • tiled/extensions/export_lua_and_defold.js owns Tiled export/localization.
  • hooks/editor_commands.lua registers the Defold editor commands.
  • Prepare & Check owns tilesource/tilemap preparation and generated tile settings.
  • Prepare & Check owns baked room collections/factories and invokes enemy/music sync.
  • mvtk/editor/layout_editor/ owns in-game room placement UX.
  • Layout Editor Export owns the published runtime layout/minimap artifacts.
  • mvtk/rooms/runtime_layout_loader.lua prefers the published local runtime layout.
